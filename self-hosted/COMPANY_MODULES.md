# Company modules and licences

The core package includes properties, rooms/whole-house rentals, reservations, guest records, stay invoices and accommodation payments. Optional module IDs are `housekeeping`, `accounting`, `pos`, `swimming`, `inventory`, and `integrations`. The Accounting module covers expense and income records, categories and financial reports; basic accommodation payment collection remains part of core. The Integrations module provides n8n API tokens, approved changes and webhooks.

## Seller workflow

Keep the Ed25519 private key on your issuing computer. The customer installation receives only the public verification key. Run `node tools/licence.mjs modules` to list the available modules. Issue a licence with the customer's installation ID, company, subscription term, property limit and purchased module list, for example:

```sh
node tools/licence.mjs issue loomi-private.pem INSTALLATION_ID "Customer Company" yearly 2 customer-licence.json --modules housekeeping,accounting,inventory
```

Use `--modules all` for all optional modules, or `--modules none` for core only. Omitting this option preserves the previous full-package issuing behavior but writes an explicit module list. Unknown and duplicate module IDs are rejected. Monthly, yearly and permanent licences support the same module selection. Existing valid signed licences without a module claim retain full module access for backward compatibility; replace them with an explicit module licence when changing a customer's package. Module claims are signed with the other licence fields and cannot be modified without invalidating the signature.

## Customer workflow

In Settings → Company features, owners and administrators can enable or disable modules included in their licence. Unpurchased modules are locked and show that a licence upgrade is required. The settings apply to the entire installation/company across all properties, not just the selected hotel. Staff action permissions still apply after a module is enabled. Employees cannot change company modules.

For an upgrade, issue a replacement signed licence for the same installation ID. The company owner uploads it in Company features. Existing activation rules still enforce expiry, installation and property limits. Data and accounts are preserved; the customer can then enable the new module. No purchase portal or automated billing is included.

Disabled modules disappear from navigation and their GET/POST endpoints return 403, including requests from owners. Housekeeping changes in the shared property API also require the enabled module. The normal checkout transition may still mark a room dirty; check-in does not require the cleaning dashboard when it is disabled. Existing out-of-service room flags continue to block availability; resolve those flags before disabling Housekeeping if necessary. Customer settings use optimistic version checks and append an audit entry containing the actor, time and enabled module list.

Disabling a module keeps its records. Finish open POS orders, swimming vouchers and inventory requests before turning them off; their module actions remain blocked until re-enabled. Financial records already generated by those modules remain in accounting reports if Accounting is enabled, and historical stay invoices retain applicable POS charges. Module choices do not erase financial history.

Disabling Integrations blocks bearer-token API access, integration management and webhook dispatch. Existing tokens, approval requests and pending deliveries are preserved. No new events are queued for disabled integrations. Housekeeping API mutations and approval of pending housekeeping changes are blocked when Housekeeping is not enabled; cleaning fields are omitted from n8n room/report reads and pending cleaning webhooks pause. All gates recheck current entitlement on subsequent requests, including previously issued tokens. Other already-open browser sessions may need a refresh to update navigation; API enforcement is immediate for new requests.

## Hosted demonstration

The Sites version exposes all supported screen modules for testing company switches. It labels itself as a demonstration and does not pretend to use a commercial signed licence. The n8n integration runtime and signed module enforcement are supplied in the self-hosted version saved to GitHub. Server deployment remains a separate step.
